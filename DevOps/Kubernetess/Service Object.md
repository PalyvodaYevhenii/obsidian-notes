**Service** в Kubernetes — это абстракция, которая предоставляет единую, постоянную точку доступа (IP-адрес и DNS-имя) к группе динамически меняющихся подов.

Поскольку поды эфемерны (они постоянно пересоздаются при сбоях или обновлениях и получают новые IP-адреса), обращаться к ним напрямую ненадёжно. `Service` решает эту проблему, выступая в роли внутреннего балансировщика нагрузки.

---

Как это работает

1. **Метки (Labels) и селекторы (Selectors):** Вы задаёте в манифесте `Service` селектор (например, `app: backend`). Сервис автоматически находит все поды с такой меткой.
2. **Endpoints / EndpointSlices:** Kubernetes в реальном времени обновляет список IP-адресов здоровых подов, подходящих под селектор.
3. **Маршрутизация:** Компонент `kube-proxy` на каждом узле настраивает сетевые правила (через iptables или IPVS), чтобы трафик, приходящий на IP сервиса, равномерно распределялся между живыми подами.

---

Основные типы Service

| Тип                            | Назначение и область видимости                                                                                                                         |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **ClusterIP** _(по умолчанию)_ | Выдаёт внутренний IP, доступный **только внутри кластера**. Используется для общения микросервисов между собой (например, фронтенд стучится в бэкенд). |
| **NodePort**                   | Открывает статический порт (обычно из диапазона `30000–32767`) на **каждом узле** кластера. Позволяет обратиться к приложению снаружи по .             |
| **LoadBalancer**               | Создаёт внешний облачный балансировщик нагрузки (в AWS, GCP, Azure и др.) с публичным IP-адресом и направляет трафик на ваш сервис.                    |
| **ExternalName**               | Не проксирует трафик, а просто возвращает CNAME-запись, связывая имя сервиса внутри кластера с внешним доменом (например, `://external.com`).          |

## Commands

### Просмотр и диагностика

- `kubectl get svc` — список сервисов в текущем namespace (сокращение от `services`).
    
- `kubectl get svc -A` — список сервисов во всех namespace.
    
- `kubectl get svc -o wide` — показать сервисы вместе с их `SELECTOR`.
    
- `kubectl describe svc <name>` — подробная информация: порты, селекторы, IP, события и список `Endpoints`.
    
- `kubectl get ep <name>` — проверить **Endpoints** (IP-адреса подов, на которые реально идёт трафик). Если здесь пусто — метки в `selector` сервиса не совпадают с метками подов.
    
- `kubectl get endpointslices -l kubernetes.io/service-name=<name>` — современный аналог `endpoints` для крупных кластеров.
    

### Создание и изменение

- `kubectl apply -f service.yaml` — создать или обновить сервис из манифеста.
    
- `kubectl expose deployment <deploy-name> --port=80 --target-port=8080` — быстро создать `ClusterIP`-сервис поверх существующего Deployment.
    
- `kubectl expose deployment <deploy-name> --port=80 --target-port=8080 --type=NodePort` — то же самое, но с типом `NodePort` (или `LoadBalancer`).
    
- `kubectl create service clusterip <name> --tcp=80:8080 --dry-run=client -o yaml > svc.yaml` — сгенерировать шаблон YAML без применения в кластер.
    
- `kubectl edit svc <name>` — открыть манифест сервиса для правки в редакторе.
    
- `kubectl patch svc <name> -p '{"spec": {"type": "NodePort"}}'` — быстро сменить тип сервиса одной командой.
    
- `kubectl delete svc <name>` — удалить сервис.
    

### Доступ и проверка сети

- `kubectl port-forward svc/<name> 8080:80` — пробросить порт сервиса на локальную машину (`localhost:8080` → порт `80` сервиса).
    
- `kubectl run curl-test --rm -it --image=curlimages/curl -- sh` — запустить временный под внутри кластера для проверки доступности сервиса по внутреннему DNS:
    
    Bash
    
    ```
    curl http://<svc-name>.<namespace>.svc.cluster.local:<port>
    ```
